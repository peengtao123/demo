# 系统管理功能测试指南

## 测试准备

### 1. 初始化数据库权限

在启动应用前，先执行SQL脚本添加系统管理菜单权限：

```bash
# 连接到H2数据库（应用启动后）
# 访问 http://localhost:8080/h2-console

# 执行以下SQL（或运行完整的 init_menu_permissions.sql）
INSERT INTO permissions (name, code, description, icon, type, parent_id, sort_order, status) 
VALUES ('系统管理', 'profile:menu', '个人信息和密码管理', 'bi-gear', 'MENU', NULL, 6, true);

INSERT INTO permissions (name, code, description, icon, type, parent_id, sort_order, status) 
VALUES ('个人信息', 'profile:view', '查看和编辑个人信息', 'bi-person', 'MENU', 
        (SELECT id FROM permissions WHERE code = 'profile:menu'), 1, true);

INSERT INTO permissions (name, code, description, icon, type, parent_id, sort_order, status) 
VALUES ('修改密码', 'profile:password', '修改登录密码', 'bi-key', 'BUTTON', 
        (SELECT id FROM permissions WHERE code = 'profile:menu'), 2, true);
```

### 2. 为用户分配系统管理权限

确保测试用户拥有 `profile:menu` 和 `profile:view` 权限。

## 测试步骤

### 测试1：访问个人信息页面

**步骤：**
1. 启动应用：`mvn spring-boot:run`
2. 浏览器访问：`http://localhost:8080/login`
3. 使用已有账号登录（如 admin/123456）
4. 点击左侧菜单"系统管理"
5. 验证是否正确显示个人信息页面

**预期结果：**
- ✅ 左侧菜单显示"系统管理"选项
- ✅ 页面标题显示"👤 个人信息"
- ✅ 显示用户头像（或首字母占位）
- ✅ 显示用户名、姓名、邮箱、注册时间
- ✅ 表单包含：姓名、邮箱（禁用）、电话、年龄、头像URL、备注字段
- ✅ 底部有"保存修改"和"修改密码"按钮

### 测试4：修改密码 - 正常流程

**步骤：**
1. 输入正确的原密码（如：123456）
2. 输入新密码（如：newpass123）
3. 观察密码强度指示器
4. 再次输入新密码确认
5. 点击"确认修改"按钮

**预期结果：**
- ✅ 密码强度指示器显示相应强度（弱/中/强）
- ✅ 实时显示"✓ 密码一致"提示
- ✅ 提交后自动退出登录
- ✅ 跳转到登录页面
- ✅ 使用新密码可以成功登录
- ✅ 审计日志中记录PASSWORD_CHANGE操作（包含IP地址）

### 测试5：修改密码 - 错误场景

#### 5.1 原密码错误
**步骤：**
1. 输入错误的原密码
2. 输入新密码并确认
3. 点击"确认修改"

**预期结果：**
- ❌ 显示红色错误提示："原密码不正确"
- ❌ 停留在当前页面
- ❌ 密码未修改

#### 5.2 两次密码不一致
**步骤：**
1. 输入正确的原密码
2. 输入新密码：newpass123
3. 确认密码：newpass456
4. 点击"确认修改"

**预期结果：**
- ❌ 实时显示"✗ 两次输入的密码不一致"
- ❌ 如果绕过前端验证，后端也会拒绝
- ❌ 显示错误提示

#### 5.3 新密码长度不足
**步骤：**
1. 输入正确的原密码
2. 输入短密码：12345（少于6位）
3. 确认密码：12345
4. 点击"确认修改"

**预期结果：**
- ❌ HTML5验证阻止提交（minlength="6"）
- ❌ 或后端返回错误："新密码长度不能少于6位"

## 常见问题排查

### 问题1：菜单不显示"系统管理"

**原因：** 数据库中缺少相应的权限记录

**解决：**
```sql
-- 检查是否存在系统管理菜单
SELECT * FROM permissions WHERE code = 'profile:menu';

-- 如果不存在，执行初始化脚本
-- 或手动插入上述SQL
```

### 问题2：访问个人信息页面报错

**原因：** 用户未登录或会话过期

**解决：** 重新登录系统

### 问题3：修改密码时提示"原密码不正确"

**原因：** 
1. 确实输入了错误的原密码
2. 密码加密方式不一致

**解决：** 
1. 确认输入的原密码正确
2. 检查数据库中存储的密码是否已正确加密

### 问题4：审计日志没有记录

**原因：** AuditLogService未正确注入或配置

**解决：**
1. 检查UserService中是否正确注入了AuditLogService
2. 查看应用日志是否有相关错误

## 性能测试建议

1. **并发测试：** 多个用户同时修改个人信息
2. **压力测试：** 频繁修改密码（应有限制机制）
3. **安全性测试：** 尝试SQL注入、XSS攻击等
