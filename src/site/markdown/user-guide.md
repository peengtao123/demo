# 用户指南

本文档详细介绍 Demo Project 的所有功能模块和使用方法。

## 1. 系统登录

访问 http://localhost:8080 进入登录页面，使用以下默认账号登录：

| 角色 | 用户名 | 密码 | 权限说明 |
|------|--------|------|----------|
| 管理员 | admin | admin123 | 拥有所有系统管理权限 |
| 编辑者 | editor | editor123 | 可以编辑内容，无系统管理权限 |
| 访客 | viewer | viewer123 | 仅查看权限 |

## 2. 仪表盘

登录后进入系统仪表盘，显示：

- 系统统计信息（用户数、角色数、权限数等）
- 最近操作记录
- 快捷操作入口

## 3. 用户管理

### 3.1 用户列表

**路径：** `/admin/users`

**功能：**
- 查看所有用户列表
- 按用户名、邮箱搜索
- 分页显示
- 快速启用/禁用用户

### 3.2 创建用户

点击"新建用户"按钮，填写表单：

- **用户名**：唯一标识，必填
- **邮箱**：用于接收通知，必填
- **密码**：至少6位，必填
- **姓名**：显示名称，选填
- **角色**：可分配多个角色
- **状态**：启用/禁用

### 3.3 编辑用户

在用户列表中点击"编辑"按钮，可以修改用户信息。编辑时可以：

- 修改基本信息（邮箱、姓名等）
- 重新分配角色
- 重置密码
- 更改用户状态

### 3.4 删除用户

点击"删除"按钮，确认后永久删除用户。注意：

- 删除操作不可恢复
- 会同时删除用户的角色关联关系
- 会记录审计日志

### 3.5 查看用户详情

点击"详情"按钮，查看用户的完整信息，包括：

- 基本信息
- 已分配的角色列表
- 创建时间和更新时间
- 最后登录时间

## 4. 角色管理

### 4.1 角色列表

**路径：** `/admin/roles`

显示系统中所有角色及其基本信息。

### 4.2 创建角色

点击"新建角色"按钮，填写：

- **角色名称**：唯一标识，如 ADMIN、EDITOR
- **显示名称**：中文名称，如"管理员"
- **描述**：角色用途说明
- **权限**：勾选该角色拥有的权限

**提示：** 可以使用"全选/取消全选"快速选择权限。

### 4.3 分配权限

在角色编辑页面，可以看到所有可用权限的复选框列表：

- 权限按模块分组显示
- 每个权限显示图标、名称和 code
- 支持多选
- 编辑时自动选中已有权限

### 4.4 从模板创建

系统预置了标准角色模板：

- **ADMIN**：管理员，拥有所有权限
- **EDITOR**：编辑者，拥有内容编辑权限
- **VIEWER**：访客，仅查看权限

创建新角色时可以选择从模板复制权限配置。

## 5. 权限管理

### 5.1 权限列表

**路径：** `/admin/permissions`

显示所有权限，支持按类型筛选（菜单/按钮）。

### 5.2 创建权限

点击"新建权限"，填写：

- **权限名称**：显示名称
- **权限Code**：唯一标识，格式：module:action（如 user:view）
- **类型**：菜单权限或按钮权限
- **URL**：菜单对应的路径（仅菜单类型需要）
- **图标**：Bootstrap Icons 类名（仅菜单类型需要，如 bi-house）
- **排序号**：控制显示顺序
- **父权限**：构建层级关系
- **描述**：权限说明

**注意：** 选择"按钮"类型时，URL 和图标字段会自动隐藏。

### 5.3 权限类型

**菜单权限：**
- 控制左侧导航菜单的显示
- 需要有 URL 和图标
- 可以设置父子关系形成多级菜单

**按钮权限：**
- 控制页面中按钮的显示
- 不需要 URL 和图标
- 通过 Thymeleaf 自定义标签控制

## 6. 审计日志

### 6.1 日志列表

**路径：** `/admin/audit-logs`

记录系统所有重要操作，包括：

- 用户登录/登出
- 用户 CRUD 操作
- 角色和权限变更
- 其他敏感操作

### 6.2 筛选日志

支持多维度筛选：

- **操作人**：按用户名搜索
- **操作类型**：CREATE、UPDATE、DELETE、LOGIN 等
- **目标类型**：USER、ROLE、PERMISSION 等
- **时间范围**：起始和结束时间

### 6.3 查看日志详情

每条日志包含：

- 操作人信息
- 操作时间和 IP 地址
- 操作类型和目标对象
- 变更前后值对比
- 操作结果（成功/失败）

### 6.4 删除日志

支持批量删除和单条删除，删除前需要确认。

## 7. 个人中心

### 7.1 个人信息

**路径：** `/admin/profile`

查看和修改当前登录用户的基本信息。

### 7.2 修改密码

**路径：** `/admin/profile/password`

修改当前用户密码，需要输入：

- 当前密码
- 新密码（至少6位）
- 确认新密码

## 8. 权限控制机制

### 8.1 动态菜单

系统根据当前用户的权限动态生成左侧菜单：

- 只展示用户有权限访问的菜单
- 支持多级菜单嵌套
- 菜单项带图标和悬停提示

### 8.2 按钮级控制

在页面中使用 Thymeleaf 自定义标签控制按钮显示：

```html
<button perm:hasPermission="user:create">新建用户</button>
<button perm:hasPermission="user:edit">编辑</button>
<button perm:hasPermission="user:delete">删除</button>
```

如果用户没有对应权限，按钮会被自动隐藏。

### 8.3 API 拦截

后端使用 `@RequirePermission` 注解保护 API：

```java
@RequirePermission("user:delete")
@PostMapping("/users/{id}/delete")
public ApiResponse deleteUser(@PathVariable Long id) {
    // ...
}
```

无权限访问时返回 403 Forbidden。

## 9. 最佳实践

- **定期备份数据**：虽然使用 H2 数据库，但生产环境建议迁移到 MySQL/PostgreSQL
- **最小权限原则**：为用户分配刚好够用的权限，避免过度授权
- **定期审计日志**：检查异常操作，及时发现安全问题
- **密码策略**：强制使用强密码，定期更换
- **角色模板**：使用预置角色模板快速创建新用户角色

## 10. 故障排查

### 10.1 菜单不显示

**问题：** 登录后左侧菜单为空

**原因和解决：**
- 检查用户是否分配了角色
- 检查角色是否分配了权限
- 确认权限类型为"菜单"且配置了 URL
- 查看浏览器控制台是否有 JavaScript 错误

### 10.2 按钮不显示

**问题：** 页面上的按钮看不到

**原因和解决：**
- 检查当前用户是否有对应权限
- 确认权限 Code 与模板中的 `perm:hasPermission` 一致
- 检查 Bootstrap Icons CSS 是否正确加载

### 10.3 403 错误

**问题：** 访问某些功能时返回 403 Forbidden

**原因和解决：**
- 当前用户缺少必要权限
- 联系管理员分配相应权限
- 检查 `@RequirePermission` 注解的权限 code 是否正确
